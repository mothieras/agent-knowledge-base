# 产品需求：自托管知识检索服务

> 状态：需求访谈已确认，尚未代表功能交付。用户已选择 **A：五天检索优先演示版**。
> 本文规定做什么；[技术设计](DESIGN.md)规定实现边界；[路线计划](../ROADMAP.md)规定执行与验收顺序。当前实际能力及验证证据只以根 [README](../README.md) 为准。

## 1. 定位与优先级

完整产品定位：以 RAG 检索为核心、内置 Agent 为可选增强，通过同一个 FastAPI 应用提供 HTTP API 和 MCP 的自托管知识服务。

首要目标是学习与求职展示：用可复现证据说明检索是否准确、答案依赖哪些材料、Agent 编排带来了什么收益和成本。接口数量、管理功能和部署包装是加分项，不替代检索质量。

内容可以是文档、笔记、记忆或反馈，但服务只处理文本与元数据。存储“记忆”不等于自动提取、合并或遗忘记忆；存储 feedback 不等于系统会自动学习或调整排序。

“本地搜索”指在自己控制的资料和索引中搜索，不是复制互联网搜索引擎。不内置 Web Search、Web Fetch 或浏览器工具；外部 Agent 可以自行组合这些能力。

优先级：**检索与证据 → 可比较的问答行为 → MCP/HTTP 实际接入 → 可复现交付 → 协作管理**。

## 2. 使用者与场景

- 主要交付对象：项目作者，以及评审项目工程能力的开发者、面试官。
- 首个真实 MCP 客户端：Pi，通过 `pi-mcp-adapter` 接入。
- 独立应用调用者：通过 HTTP 获得证据，或委托内置问答。
- Gradio：保留为问答演示客户端，不新增文档管理后台。

典型演示：将固定版本的技术资料入库，在 Pi 中查询“某项技术如何实现”，返回相关片段与原文位置；Pi 使用自己的模型回答。相同问题还可以通过本服务的普通 RAG、Agentic RAG 两种模式回答，比较结果、检索轨迹、延迟与成本。

验收语料沿用现有公开中文 RAG 教程。通用记忆、反馈等用项目自有小型样例证明数据形态可接收，不据此宣称在所有领域上都有同样质量。

## 3. 两个范围，不混写

### 3.1 五天版本：受控资料库、检索优先

五天从实施开始计为 Day 1–5，不把文档编写视作能力已经完成。目标是一个可演示、可复测的端到端切片，不是完整共享知识服务。

| ID | 本次必须交付 | 验收重点 |
|---|---|---|
| D-01 | 生成模型可选的入库和直接检索 | 不配置生成模型凭据，也能构建索引、启动服务、查找和回查证据；本地 embedding 仍需模型文件和算力 |
| D-02 | 固定资料的离线导入 | 由部署者通过受控本地脚本/CLI 导入文本与元数据、MD、TXT、文本型 PDF；不提供在线上传或 MCP 写入 |
| D-03 | HTTP 与 MCP 只读检索 | 共用检索与证据契约，支持搜索与按标识读取证据，不需要启动问答图 |
| D-04 | 单图普通 RAG | 固定检索 → 组织上下文 → 生成；不是工具循环，不为单图另配模型密钥 |
| D-05 | 双图 Agentic RAG | 本项目内部的 LangGraph 主图＋检索子图，可在一次请求中改写、拆解、并行补查与聚合；复用同一生成模型配置 |
| D-06 | 证据约束与显式结果 | 回答、需要澄清、拒答三种结果；有依据的部分可回答，缺失部分明确指出；不把模型常识伪装成资料结论 |
| D-07 | 单次请求语义 | 不延续历史、不恢复 HITL；有歧义时返回澄清提示，调用者补全后作为新请求提交 |
| D-08 | 可回查的引用 | 搜索结果与答案引用绑定固定索引快照、来源、片段和规范化原文位置；不存在的引用不能返回为有效证据 |
| D-09 | 真实比较和回归证据 | 冻结评测契约；记录直接检索、单图、双图的相关指标及 badcase，不预设双图一定更好 |
| D-10 | 交付闭环 | Python 原生与 Docker 均能启动；Pi 实测接入；沿用 Gradio 问答展示；附可复现步骤和限制 |

D-02 的文件处理不包括扫描件 OCR、图片理解或复杂表格保真。解析失败、空文本、不支持格式须显式报错，不静默当作入库成功。

本次只维护一个部署者控制的、在线只读的资料快照。所有获准访问者看到相同数据；不能装入需要按 Agent 隔离的资料，也不宣传“私有知识库权限隔离”。更新资料采用停止服务后离线重建，不承诺热更新。

### 3.2 完整目标：明确顺延，未取消

| ID | 后续共享知识服务需求 |
|---|---|
| F-01 | 每个 Agent 使用独立凭据，服务端识别身份；不能靠修改 `agent_id` 或文档 ID 越权 |
| F-02 | 公共区与各 Agent 私有区；默认查询公共区＋自己私有区，可显式缩小范围 |
| F-03 | 所有已认证 Agent 可新增、修改、删除公共内容；只能管理自己的私有内容 |
| F-04 | HTTP/MCP 通用文本写入，以及文件异步入库任务；返回任务 ID 和可查询状态/失败原因 |
| F-05 | 修改、删除校验期望修订号；冲突明确返回，不默认后写覆盖，不自动合并正文 |
| F-06 | 新版本完整就绪前旧版本继续可查；失败不破坏旧版；发布后不混用新旧内容 |
| F-07 | 删除生效后新查询不可命中；陈旧入库任务不得重新发布、复活内容 |
| F-08 | 保留文档历史，默认只检索当前版本；历史回查也检查当前权限和删除状态 |
| F-09 | 全部入口、父文档回查、任务状态、图工具、引用都使用同一访问边界 |

这些能力是后续目标，**不作为五天版本已经交付的标签**。记录 F 系列需求不等于本轮开始实现控制平面、任务队列或版本管理系统。

### 3.3 不纳入产品目标

- 自动记忆提取、遗忘、用户画像、反馈驱动学习。
- 内置联网搜索、网页抓取、Chrome MCP 或任意代码执行工具。
- 跨请求聊天历史、会话恢复、PostgresSaver 产品能力。
- DOCX、扫描 PDF/OCR、图像语义理解。
- 管理后台、通用多租户 SaaS、OIDC/RBAC 平台、计费、Kubernetes、高可用。

本地生成模型不是首版真实验收项。兼容的模型接口可以保留，但未经测试不能宣称本地模型已支持。

## 4. 模型与编排契约

| 入口/模式 | 谁负责生成 | 服务端生成模型是否必需 |
|---|---|---|
| 直接检索 | 调用者决定，外部 Agent 可使用自己的模型 | 否 |
| `rag` 单图问答 | 本服务，固定流水线 | 是 |
| `agentic` 双图问答 | 本服务，受预算约束的 Agent | 是 |

- 单图与双图共用一套服务端模型配置，不按图要求不同 API key。
- “无生成模型”不等于“无任何模型”或“首次启动无需下载”：向量检索仍依赖本地 embedding 和 sparse 模型。
- 检索/入库路径不得隐式执行 LLM 查询改写、摘要或生成。
- 未配置生成模型时只读检索保持 ready，问答能力明确 unavailable；调用问答返回可识别错误，不能伪造答案或拒答。
- MCP 是接入协议，不把客户端模型自动提供给本服务；不依赖 MCP Sampling。
- 可选内置问答会将问题和选中的证据发送给配置的生成模型。自托管不等于所有内容永不出机器。

## 5. 证据与问答规则

1. 直接检索返回片段与结构化来源，不只返回一段生成摘要。
2. 片段位置指向规范化后的父文本，使用明确的字符坐标；不冒充 PDF 页码或原始文件字节偏移。
3. 答案引用必须指向本次实际取得的证据。引用可回查不代表语义必然正确，两者分别验证；D-06 必须通过冻结样本的语义支持审计，不能仅凭 span/hash 校验通过就宣称完成。
4. 无命中与检索故障不同：无命中是正常空结果，故障是错误，不能被统计成成功拒答。
5. 模型只能回答证据支持的内容；证据部分充足时返回有依据的部分及明确缺口；完全不足时拒答。
6. 歧义返回 `clarification_required`，这是本次完成结果，不是等待恢复的服务器会话。
7. 材料冲突时应指出冲突和各自版本，不能仅凭排名高就判定为事实。
8. 文档内容是数据，不是工具权限或系统指令。多个 Agent 写入的材料也不天然可信。
9. 五天版的证据稳定性以仍保留的固定索引快照为边界。离线重建后旧快照若已移除，应明确告知证据失效，不能用同名新文档替代旧引用。
10. manifest 来源版本、编辑修订号、索引快照是不同概念。五天版不宣称动态版本发布、自动选择业务最新版本或有效期过滤已经完成。

## 6. 运行与安全边界

- 首个验收环境：用户自己的 Apple M4、24 GiB Mac；记录具体 macOS、Python、CPU/加速设备和 Docker 资源配置。
- 规模目标：约 100 份文档、1 万检索块、3 个并发请求。它们是待验证目标，不是当前容量声明。
- 受控合成规模数据单独运行负载测试，不混入质量语料冒充检索改进。
- 直接检索与生成问答分别记录 P50/P95、超时、错误、资源使用；不承诺未测出的亚秒延迟。
- 首版仅本机受控演示，不暴露公网。技术设计采用最小部署级凭据防止无意访问；所有持有者权限相同，不构成 F-01 的 Agent 身份模型。
- Gradio 不持有数据库或图；不新增文档/身份后台。服务密钥不进入页面、响应、日志或镜像。
- 资料、模型缓存、索引不因容器退出丢失。运行时不与离线入库/eval 进程争用同一 embedded Qdrant 目录。
- Pi adapter 支持 Streamable HTTP/Bearer 已有本机静态源码依据；真实连通、认证和返回内容消费仍须实测。

## 7. 验收证据

下面是门禁设计，不是当前测试结果。

| ID | 验收场景 | 必须留下的证据 |
|---|---|---|
| A-01 | 清除生成模型配置后离线入库、启动、HTTP/MCP 搜索及原文回查 | 自动化测试＋真实运行记录；生成模型调用次数为 0 |
| A-02 | 同问题、同快照，通过应用服务/HTTP/MCP 查询 | 使用共同响应预算，裁剪后的有序命中 ID、来源、SHA-256、returned_k 一致；原始检索另计，不改写证据 |
| A-03 | 普通 RAG 与双图 Agent 分别执行单次问答 | mode、decision、引用、工具轨迹、耗时、token/成本；不得带入其他请求状态 |
| A-04 | 可回答、歧义、无答案、冲突资料及错误路径 | 显式 decision；引用有效性及冻结样本语义支持审计；检索/模型故障不伪装成拒答 |
| A-05 | 同一问题重跑、旧快照失效、伪造证据 ID | 固定快照内容可精确回查；无效/过时 ID 不返回别处内容 |
| A-06 | 固定质量集完整执行 | 全量 per-item 结果、冻结配置及 badcase；0 ERROR/0 SKIP 才可标记评测通过 |
| A-07 | Pi 实际接入 | 工具发现、正确/错误凭据、搜索、原文回查及至少一次答案消费记录；不只看工具列表 |
| A-08 | Python 与 Docker 空数据流程 | 依赖/模型准备、离线入库、启动、health ready、HTTP/MCP smoke；没有生成模型也可运行 |
| A-09 | 规模和并发目标 | 实际文档/块数、3 并发负载脚本、P50/P95、错误与内存报告，无法完成时如实标记未验收 |
| A-10 | 现有测试与新协议回归 | 全量 pytest 通过；有真实本地索引时不得靠 skip 替代最终集成验收 |

质量评测以原 30 题和历史报告为回归资产，另外冻结至少 40 条实际检索计分题及相关性标注。单次问答的澄清终止语义独立计分，不能把旧 HITL 的暂停率与新结果直接混为同一指标。历史 runner 误名为 precision 的非误拒比例也单独保留，新拒答 precision 使用标准 TP/(TP+FP)，定义见路线计划。

两种问答模式在相同问题、语料、retriever、模型配置下比较；分别记录不同 prompt 与调用预算。不预设双图必须晋升，不通过修改题目或删除 badcase 美化结果。具体计分和实验顺序见 [路线计划](../ROADMAP.md)。

## 8. 费用、截止时间与变更

- 截止窗口：五天，按检索优先演示版交付；后续 F 系列不隐含进入本次承诺。
- 用户允许沿用现有低成本模型执行评测，不逐轮确认费用。
- 请求、扇出、工具循环、模型重试均有边界；记录生成和 judge 的用量/估算费用，异常停止。此授权不等于购买新服务或无限消费。
- 算法升级不是五天退出条件。没有冻结评测和实证收益时保留当前 hybrid，不默认加入 jieba/RRF/reranker。
- 进度不足先停止额外算法实验、界面美化、附加客户端适配。不得通过隐藏测试失败、伪造引用或宣称未做的权限能力来赶期限。
- 最终交付清单逐项列出通过、失败和未执行。关键项未通过就不能宣布五天目标全部完成；进一步裁剪范围须再次确认。

## 9. 与旧构想的差异

- 从“企业级知识库＋Web/Chrome 工具”收敛为自托管检索服务；外部工具由调用者组合。
- 将完整共享知识层与五天受控只读演示版拆开，不把协作能力写成已交付。
- 保留真实主图/子图；新增固定普通 RAG 单图作为使用模式和比较对象。
- 从多轮聊天/HITL 恢复转为单次请求，现有 `/history`、`thread_id` 与恢复行为需要显式迁移。
- 历史技术路线中的自动版本过滤、检索算法消融可继续研究，但不是已经完成；PostgresSaver 和多轮恢复不再是产品目标。
