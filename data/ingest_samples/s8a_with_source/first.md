# 同名冲突样例 S8a（第一份）

本文件是入库管道样例集 S8 情形一的第一个文件：两份内容不同的文件被登记为同一个 source 标识提交入库。在 manifest 治理语义下这属于登记错误——同一个来源身份不能对应两份不同内容。目标行为是显式冲突报错；当前实现按"目标规范化文件已存在"处理，第二份被静默跳过，本对样例用于固定该基线。

本段是第一份文件的内容指纹：FIRST-FILE-CONTENT-A。冲突检测的难点在于"同名"的判定层级：文件名相同、stem 相同、source 标识相同是三个不同的概念。当前管线用 source 标识派生规范化文件名，因此 source 标识相同必然导向同一目标文件；冲突在文件系统层面表现为存在性检查命中，而不是显式的登记冲突。把这一隐式行为提升为显式错误类，是结果结构化任务的一部分。

本节其余内容用于把文件撑到可独立成父块的尺寸，保证本文件单独提交时走成功路径。内容刻意与第二份文件完全不同，确保任何"两份都被入库"或"第二份覆盖第一份"的缺陷都会在 store 侧留下可观测的证据：parent store 的 source 列表与规范化目录的文件清单都只应出现一个来源身份。冲突样例的价值在于让静默行为无处藏身。This is the content fingerprint of the first file: FIRST-FILE-CONTENT-A.
